# Legal

Entity, founder, and client-contract docs. **Templates and status only — not legal advice.**
Get a startup lawyer to review before signing anything, especially because we handle clients'
financial data.

> ⚠️ Never commit signed contracts with real client data or PII. Keep executed docs in a secure
> store; this folder holds **templates + a status checklist**.

## Company formation
- [ ] Entity formed (LLC vs. C-corp — C-corp if raising venture)
- [ ] Founders' agreement + **equity split** + **vesting** (4-yr / 1-yr cliff is standard)
- [ ] **IP assignment** from each founder/contractor to the company
- [ ] EIN, bank account, accounting set up
- [ ] Roles documented (incl. Cameron's role — see `../docs/decisions.md` open items)

## Client contracts (needed for forward deployment)
- [ ] **MNDA** — mutual NDA (before discovery / sharing data)
- [ ] **MSA** — master services agreement (the umbrella terms)
- [ ] **SOW** — statement of work (per engagement: scope, deliverables, price, timeline)
- [ ] **DPA** — data processing agreement (we touch financial/operational data)
- [ ] Security/data-handling addendum (see `../docs/security.md`)
- [ ] Retainer / licensing terms for ongoing management

## Hiring / contractors
- [ ] Offer + IP assignment + confidentiality for the AI engineer and any contractors

## Notes
- Forward deployment = we work inside client systems → contracts must cover data access,
  confidentiality, liability limits, and what happens to the built automations on exit.
